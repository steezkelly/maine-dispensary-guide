The production manifest will be generated by an editorial review queue that pages the operator when a `task_contract_status` field is `NEEDS_EDITORIAL_REVIEW` or `UNRESOLVED`.

## 1. Schema — `page_task_manifest`

Implements PAGE-ARCHETYPES.md §"Required page manifest fields". One row per indexable route. The manifest is a typed JSONL at `apps/maine-cannabis/docs/analytics/page_task_manifest.v1.jsonl` (created in this ticket).

### 1.1 Required fields (per spec)

```
page_id                  stable, human-readable, derived from canonical_path
canonical_path           URL path, lowercase, no trailing slash (per repo convention)
route_family             "city_guide" | "operator_profile" | "long_form_guide"
                         | "editorial_blog" | "directory" | "calculator"
                         | "data_product" | "conversion_asset" | "hub"
                         | "other"
reporting_archetype      same vocabulary as route_family — same value initially,
                         but allows drift when analytics needs a different label
                         than the URL pattern (e.g. /guides/<operator-slug> that
                         is editorially a city/hub would be route=city_guide /
                         archetype=conversion_asset)
primary_task_family      one of:
                         local_store_discovery | operator_profile |
                         market_entry_analysis | visitor_buying_guide |
                         regional_discovery_hub | regulatory_task |
                         how_to_task | data_research | calculator_decision_tool |
                         editorial_exploration
secondary_task_families  optional list, free-text only if "OTHER_REVIEW_REQUIRED"
task_contract_status     CONFIRMED | PROVISIONAL | NEEDS_EDITORIAL_REVIEW |
                         UNRESOLVED
serp_promise_family      local_store_discovery | named_operator |
                         market_entry | visitor_local | how_to |
                         regulatory | calculator | data_research |
                         product_or_category | branded | generic_topic |
                         OTHER_REVIEW_REQUIRED
promise_task_alignment    ALIGNED | PROMISE_BODY_MISMATCH |
                         QUERY_BODY_MISMATCH | QUERY_PROMISE_MISMATCH |
                         MULTI_INTENT_LANDING | INSUFFICIENT_QUERY_DATA
entity_scope             town | operator | region | state | topic | product |
                         calculator | dataset | other
entity_id                stable, slug-derived for town/operator; null otherwise
geo_scope_id             stable, slug-derived for town/region; "Maine" for state
regional_navigation_cluster_ids  optional list — only when the page is in a hub
demand_regime            evergreen | seasonal | event_driven | one_time |
                         consolidating | emerging | UNKNOWN
market_form              saturated | underserved | competitive |
                         opportunistic | regulatorily_constrained |
                         UNKNOWN
recurrence_expectation   low | medium | high
content_depth_band       short | medium | long | very_long
template_family          filename glob pattern; e.g. "city_guide-with-faq"
major_content_change_at  ISO date or null
instrumentation_version  "v0" (current; nothing wired) | "v1" (after Tickets 006+)
approved_progression_families
                         list of progression families the page SHOULD drive
manifest_evidence        object: { title: <h1 verbatim>, h1: <h1 verbatim>,
                         description: <meta description verbatim>,
                         topics_from_frontmatter: [...],
                         editorial_review_notes: <string|null> }
manifest_version         "1"
```

### 1.2 Schema enforcement

The schema is enforced on write by a Node script `apps/maine-cannabis/scripts/analytics/page-manifest-validate.cjs` (created in a separate, follow-up ticket; for now, the parent hand-validates each new row). Required fields: all of §1.1 except `secondary_task_families`, `manifest_evidence.*` granular fields, and the geo/navigation-cluster fields, which are null when not applicable.

### 1.3 Promotion rule

`task_contract_status` is `CONFIRMED` only when:
- an editorial reviewer signed off on the row (recorded in `manifest_evidence.editorial_review_notes`);
- and `promise_task_alignment` is not `PROMISE_BODY_MISMATCH` (it may be the others; multi-intent and query-data-sparse pages are honest cases).

Default for any page written without an editor's note: `PROVISIONAL` until review. Pages flagged in the corpus audit (`NEEDS_EDITORIAL_REVIEW`) are listed in §4.

## 2. Schema — `instrumentation_surface_manifest`

Implements SOURCES.md §A7. One row per **instrumentable** surface (FAQ/CTA/TOC/search/etc.). The manifest lives at `apps/maine-cannabis/docs/analytics/instrumentation_surface_manifest.v1.jsonl`.

### 2.1 Required fields

```
surface_id            stable, "faq", "cta", "toc", "search", "directory",
                      "store_select", "calculator_start", "calculator_result",
                      "conversion_start", "conversion_complete",
                      "dataset_download", "methodology_select",
                      "source_select", "page_engaged", "scroll_progress"
canonical_path        URL path the surface lives on (or "*" for global)
page_id               foreign-key into page_task_manifest
stable_element_id     CSS selector or data-* attribute (used for matching)
instrumentation_expected  bool — is the surface designed to emit an event?
instrumentation_version   "v0" | "v1"
privacy_classification    "anonymous_aggregate" | "pseudonymous_identifier"
                          | "user_provided_text" | "user_provided_identifier"
                          | "none"
coverage_status           INSTRUMENTED | WIRED_BUT_SILENT | NOT_INSTRUMENTED
expected_event_names      list of event names this surface should emit
```
